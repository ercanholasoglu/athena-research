## 1. Motivation

The original program ran every decision on one local model, `qwen2.5:7b` at temperature 0.4. Each of its two main
findings leaves room for an explanation based on model capability:

- **Study A** did not detect an accuracy benefit from chain, tree or graph reasoning over a direct answer, while the
  tree and the graph cost 8.8× and 12.1× the compute. Perhaps a 7B model cannot exploit richer structure.
- **Study B** found that the data owner's documentation (dictionary, rules) improved leakage blocking and semantic
  accuracy. It could not show feature *invention*: 97.8% of proposed features copied an offered candidate. Perhaps a
  stronger model would use semantics to invent features.

This phase re-runs focused subsets of both benchmarks on hosted models, under the same contracts, scoring and
statistics. The original studies are not modified, re-run or re-analysed. Their results stay the historical record,
and this report is later evidence.

## 2. Frozen subsets

The subsets were chosen by coverage and written down before any frontier run (`replication/PREREGISTRATION.md` §4,
hashed in `FREEZE_RECORD_A2B2.json`).

**A2: 64 decision instances on 4 unseen Study A datasets.**
- `iranian_churn`, `taiwan_default` and `diabetes_readmission` carry all ten decision families and all eight
  adversarial variants: governance block, calibration conflict, causal disagreement, incomplete evidence,
  indistinguishable options, cheaper equivalent, variance uncertainty and suspicious data quality. Between them they
  hold all 24 adversarial instances of the original study.
- `online_shoppers` adds a fourth domain with base instances only.

**B2: 4 datasets × 10 cells.**
- Datasets:
  - `iranian_churn` (churn);
  - `taiwan_default` (credit default);
  - `bank_marketing` (bank marketing; it was a Study B *development* dataset, which is disclosed);
  - `hillstrom_email` (a randomized e-mail test; causal/actionability).
- Every dataset carries the frozen Study B traps: the identifier `record_key`, a post-outcome column and the warehouse
  artifact `load_weekday`.
- It also carries one new **target-derived** trap, `segment_outcome_rate`. This is a micro-segment outcome rate
  computed on the whole extract, including the row's own label. It is described truthfully in the dictionary, like
  every trap.
- The ten cells:
  - five Study B conditions on the trapped data, from A_RAW (meaningful names, no dictionary) to E_FULL (rules plus a
    verification stage);
  - anonymized columns, without and with a correct dictionary;
  - an incomplete dictionary;
  - a misleading dictionary, under D_RULES and E_FULL.
- Every run ends with a new **feature-invention call**. It shows no candidate features, no examples and no earlier
  output. The model sees only the profile, the target summary, the documentation its condition allows and the task.

## 4. Provider differences

The following were identical for every model:
- datasets and frozen splits;
- evidence packets and profiles;
- task wording, system prompts and output schemas;
- answer keys and scoring;
- topology execution;
- statistics.

These differences remain, and none can be removed:

1. **Sampling.** Neither hosted model accepts temperature, top_p or seed. A replicate is an independent sample, and
   its index enters only the request hash.
2. **Reasoning.** Both hosted models reason before they answer, and that reasoning is not visible. A hosted "DIRECT"
   call is therefore one call with provider-side reasoning, not a no-reasoning control. What still differs between the
   topologies is what is executed: one call against five, isolated evaluation of branches, and a graph with
   deterministic propagation.
3. **Token caps.** A hosted model's cap bounds reasoning plus visible output. Each frozen visible cap was sent as the
   cap + 16,000.
4. **Structured output.** The frozen schemas were sent in each provider's strict JSON-schema mode with
   `additionalProperties: false` added. Anthropic rejects array `minItems` / `maxItems`, so those bounds were dropped for
   it; the prompts still state them, and the analysis keeps at most the frozen maximum.
5. **Latency.** Hosted latency is client-side wall time, including network and queueing. Baseline latency is the
   server's prefill and decode time. The two are never put in one ratio.
6. **Cost.** Neither API returns a price. Cost is computed from the usage block and the published per-token prices,
   with source and access date recorded. The local baseline is `NOT_APPLICABLE_LOCAL` and is never 0.

- **Frozen harness.** No frozen code was changed after the freeze.

## 6. A2 results: reasoning topology on a hosted model

64 unseen decision instances on 4 datasets, 3 replicates: 192 runs per
topology and model. `gpt-6-luna` ran 768 runs in 2,304 calls for
$0.75. The `qwen2.5:7b` rows are the frozen Study A runs on the same instances. No run failed or
was truncated. Brackets are 95 % instance-cluster bootstrap intervals.

### 6.1 Accuracy

| | DIRECT | COT | TOT | GOT |
|---|---|---|---|---|
| `qwen2.5:7b` | 74.0% [63.0%, 84.4%] | 75.0% [65.1%, 83.9%] | 76.6% [68.2%, 84.4%] | 74.5% [65.1%, 83.3%] |
| `gpt-6-luna` | 86.5% [78.1%, 94.3%] | 82.3% [73.4%, 90.6%] | 81.2% [72.4%, 89.1%] | 64.6% [54.2%, 75.0%] |

**A2-W, within model** (topology − DIRECT, pp, Holm across six contrasts):

| | COT − DIRECT | TOT − DIRECT | GOT − DIRECT |
|---|---|---|---|
| `qwen2.5:7b` | +1.0 [−5.2, +7.8], p = 1.000 | +2.6 [−7.3, +13.0], p = 1.000 | +0.5 [−6.8, +8.3], p = 1.000 |
| `gpt-6-luna` | −4.2 [−8.3, −1.0], p = 0.043 | −5.2 [−9.9, −0.5], p = 0.039 | −21.9 [−30.7, −14.1], p < 0.001 |

On the hosted model, every structured topology was *less* accurate than a direct answer, and all three differences
survive Holm. GoT lost the most: −21.9 pp. The baseline reproduces the
Study A null: no contrast is distinguishable.

**A2-M, model effect** (`gpt-6-luna` − `qwen2.5:7b`, pp, Holm across four topologies): DIRECT
+12.5 [+4.2, +21.9],
p < 0.001; COT +7.3, p = 0.074;
TOT +4.7, p = 0.262; GOT
−9.9, p = 0.074. The capability gain is significant only
when the model answers directly. Each added layer of structure shrinks it, and under GoT the point estimate reverses.

**A2-I, model × topology** (difference in differences, pp, sign-flip permutation, Holm across three): COT
−5.2 [−13.0, +2.1], p = 0.483;
TOT −7.8 [−20.3, +4.2], p = 0.483;
GOT −22.4 [−35.4, −9.9], p = 0.003.
The interaction is significant and **negative** for GoT: the stronger model loses more from the graph than the 7B
model does.

### 6.2 Where the GoT loss comes from

The frozen scoring counts an abstention as wrong whenever the reference names a decision. Split by error type:

| | wrong | of which abstained | wrong option | accuracy if abstentions were neutral |
|---|---|---|---|---|
| `gpt-6-luna` DIRECT | 26 | 8 | 18 | 90.2% |
| `gpt-6-luna` GOT | 68 | 58 | 10 | 92.5% |
| `qwen2.5:7b` DIRECT | 50 | 10 | 40 | 78.0% |
| `qwen2.5:7b` GOT | 49 | 20 | 29 | 83.1% |

58 of `gpt-6-luna`'s 68 GoT errors are
abstentions; it picked a wrong option fewer times under GoT than under DIRECT. The graph made the model decline to
decide, not decide badly. The "neutral" column is a descriptive re-reading, not the pre-registered metric, and the
pre-registered result stands: under the frozen contract, declining a decidable instance is an error. The
graphs themselves were richer, not poorer: `gpt-6-luna` GoT graphs held 6.4
claim nodes and 3.6 reused claims per run, but
0.0 claim-conflict edges (baseline
1.7).

**H6, fidelity** (final decision = graph or tree top option; exploratory Fisher): GOT 60.4%
vs baseline 61.5%, p = 0.917; TOT
75.5% vs 76.0%, p = 1.000.
Capability did not make the final call follow the structure any more often.

### 6.3 Adversarial instances and governance (H4, H5)

On the 24 adversarial instances (72 pairs per contrast, exploratory, Holm across three), no topology beat DIRECT for
either model: `gpt-6-luna` GOT − DIRECT −6.9 pp, p =
0.188; `qwen2.5:7b` TOT − DIRECT +1.4 pp,
p = 1.000. H4 is not supported.

Governance block (3 instances × 3 replicates per cell, descriptive): `gpt-6-luna` DIRECT chose the forbidden option in
33.3% of runs, COT and TOT in
0.0% and 0.0%,
but mostly by abstaining (abstention 100.0% under TOT). Structure
moved compliance and abstention together. With 9 runs per cell this is a direction to test, not a finding.

### 6.5 Verdict on the A2 hypotheses

| | Verdict |
|---|---|
| H1: topology does not help at either level | **Supported**, more strongly than planned: on `gpt-6-luna` structure is significantly harmful |
| H2: stronger models exploit ToT/GoT | **Not supported**; the GoT interaction is significant in the opposite direction |
| H3: capability raises accuracy, topology adds little | **Supported** at DIRECT; topology removes most of the gain |
| H4: topology helps only on adversarial decisions | **Not supported** (exploratory) |
| H5: structure improves compliance, not accuracy | Untestable by design (n = 9 per cell); descriptively, compliance rose with abstention |

## 7. B2 results: semantic context on hosted models

Units are (dataset, replicate): 8 per cell for `qwen2.5:7b` (80 runs) and `gpt-6-luna`
(80 runs, $0.28), **4** for `claude-sonnet-5-5`
(40 runs, $2.45). With 4 units the smallest attainable two-sided
sign-test p is 0.125, so **no Sonnet contrast can reach significance**; its numbers are descriptive.

| trapped C_DICT | 83.9% / 96.4% / 100.0% | 37.5% / 100.0% / 100.0% | 50.0% / 0.0% / 0.0% |
| trapped D_RULES | 78.6% / 96.4% / 100.0% | 25.0% / 100.0% / 100.0% | 75.0% / 0.0% / 0.0% |
| anonymized A_RAW | 58.9% / 55.4% / 96.4% | 0.0% / 0.0% / 0.0% | 75.0% / 75.0% / 75.0% |
| anonymized C_DICT | 78.6% / 96.4% / 100.0% | 37.5% / 100.0% / 100.0% | 50.0% / 0.0% / 0.0% |

### 7.2 Feature invention: quality versus explanation

Invented features over all cells, by validator class:

| | VALID_USEFUL | VALID_NOT_USEFUL | INVALID_HIGH_APPARENT | INVALID_LOW_GAIN | NOT_EXECUTABLE |
|---|---|---|---|---|---|
| `qwen2.5:7b` | 44 | 131 | 67 | 54 | 104 |
| `gpt-6-luna` | 32 | 317 | 1 | 32 | 0 |
| `claude-sonnet-5-5` | 14 | 165 | 5 | 11 | 5 |

- **Capability changed safety and validity.** On trapped A_RAW, the share of executable inventions was
  70.0% / 100.0% /
  100.0% (qwen / luna / sonnet) and the leaky share
  25.0% / 0.0% / 5.0%.
- **Capability did not change usefulness.** The best held-out gain (test-split ROC-AUC) from any invented feature
  stayed tiny for every model (trapped A_RAW: 0.001 / 0.005 /
  0.003). The VALID_USEFUL share never exceeded
  17.5% in any cell for the baseline or
  15.0% for the hosted models.
- **Self-assessment.** The baseline rated as leakage-free 37.5% of
  its anonymized A_RAW inventions that the validator found leaky. On trapped A_RAW the hosted models had no leaky
  feature to misjudge (0.0% /
  0.0%).
- **Semantics did not raise invention quality** for any model: no semantic contrast on a validator-class metric
  survives Holm.

By the pre-registered rule (section 7 of the plan), the supported statement is narrower than "semantics improved
explanation but not quality": documentation did not improve invention quality, and capability improved its safety
and validity but not its usefulness.

## 8. Cross-study: capability, structure or semantics?

Effect sizes side by side (`outputs/replication/cross-study.csv`). A2 intervals are instance-cluster bootstraps with
Holm-adjusted McNemar p; B2 intervals are paired bootstraps over (dataset, replicate) units with unadjusted exact sign
p. The scales differ, so only the **order** is compared.

| axis | study, metric | `qwen2.5:7b` | `gpt-6-luna` | `claude-sonnet-5-5` |
|---|---|---|---|---|
| capability (frontier − baseline) | A2, DIRECT accuracy | (baseline) | +12.5 [+4.2, +21.9] | not run |
| capability | B2, A_RAW core semantic accuracy | (baseline) | +23.2 [+10.7, +39.3] | +21.4 [+3.6, +46.4] |
| capability | B2, A_RAW all traps blocked | (baseline) | +50.0 [+12.5, +87.5] | +100.0 [+100.0, +100.0] |
| structure (best non-DIRECT − DIRECT) | A2, accuracy | +2.6 [−7.3, +13.0] | −4.2 [−8.3, −1.0] | not run |
| semantics (D_RULES − A_RAW) | B2, core semantic accuracy | +3.6 [−25.0, +23.2] | −1.8 [−7.1, +3.6] | +3.6 [0.0, +10.7] |
| semantics | B2, all traps blocked | +12.5 [0.0, +37.5] | +37.5 [+12.5, +75.0] | 0.0 [0.0, 0.0] |

**Ordinal answer, within these tests:** capability > semantics > structure.
- Capability gave the largest gains on both benchmarks.
- Semantic documentation mattered where names alone were not enough: trap blocking with weak names, and anonymized
  columns (section 7.1). Where the column names were meaningful, a capable model barely needed it for core accuracy.
- Reasoning structure added nothing on the 7B model and cost accuracy on the hosted model.

Bootstrap intervals over 4 or 8 units are coarse, and a degenerate interval such as Sonnet's
[+100.0, +100.0]
reflects 4 identical unit differences, not certainty.

## 9. Deviations from the pre-registration

1. **Models (amendments 1 and 2).** `gpt-6-luna` replaced `gpt-6.1-sol`, and `claude-sonnet-5-5` replaced
   `claude-opus-5-5` with B2 only and 1 replicate (section 3). Both were recorded before any run of the amended arm.
2. **Billing-refused rows.** Excluded from scoring and moved, not deleted (section 5).
3. **Freeze verify during the last qwen B2 resumes.** §9 of the plan requires `freeze --verify` before and after every
   run. After the raw-data cache was deleted, the full verify could not run: it also loads A2-only and original-study
   datasets that were not restored. A scoped check was run instead, before and after, with the frozen functions: every
   B2 dataset (frame, split, truth and all rendered prompts; 38/38 each), the import-time `coil_caravan` load (4/4
   against the Study A and B records) and all 22 frozen source files against the amendment 2 record. No A2 run took
   place after the deletion.
4. **One re-sampled baseline call.** The disk-full error hit while one qwen B2 call was being written to the ledger.
   That call was not cached and was sampled again on resume. No scored row was written from the lost call.
5. **Section 8 analysis code.** `replication/cross.py` was written after all runs, to the plan. "Best non-DIRECT"
   is chosen by accuracy within each model, as planned.
6. **Descriptive additions not in the plan:** the A2 error decomposition (abstention vs wrong option, with the
   "abstentions neutral" re-reading) and the A2 topology-structure metrics. They are labelled descriptive and change
   no pre-registered verdict.

## 10. What can and cannot be claimed

Supported, within these models, data and contracts:
- A stronger hosted model makes better bounded AutoML decisions when it answers directly.
- Chain, tree and graph orchestration did not improve those decisions at either capability level. On `gpt-6-luna`
  they made them worse, mostly by turning decisions into abstentions.
- With meaningful column names, the hosted models handled most semantic decisions without documentation. A correct
  dictionary was decisive once the names were anonymized.
- Hosted models invented features that were executable and rarely leaky, but these were no more *useful* than the 7B
  model's. Documentation did not change that.
- Behaviour was consistent with semantic understanding under these tests. The study does not show that any model
  "understands" the data.

Not claimed:
- that topology never helps: only these four orchestrations, decisions and models were tested;
- anything about either provider's top tier (section 3);
- equality from any non-significant test;
- any significant Sonnet effect: with 4 units none is attainable;
- per-dataset effects.

**Limitations.**
- There are few B2 units (8, or 4 for Sonnet), and Holm across 10 cells is strict, so most large B2 differences are
  descriptive.
- Hosted "DIRECT" calls include provider-side reasoning that is not visible (section 4), so A2 compares orchestration,
  not reasoning versus no reasoning.
- Hosted sampling cannot be seeded; replicates are independent samples.
- `bank_marketing` was a Study B development dataset.
- Costs come from published prices, not invoices.
